# **Личный отчёт QA / DevOps · Спринт 3**

**Проект:** «Система контроля посещаемости студентов» **Роль:** QA / DevOps **Спринт:** 3 (Занятия и отметка посещаемости) **Дата:** 18 ноября 2026 г.

## **1\. Цель и задачи на день**

**Цель спринта:** реализовать создание занятия и отметку статуса посещаемости для каждого студента.

**Моя задача как QA:** Подготовить тест кейсы для проверки всех статусов (присутствовал, отсутствовал, опоздал), обработки пустого списка студентов, повторной отметки, изменения статуса, а также проверить корректное отображение списка при наличии нескольких студентов.

## **2\. Что было сделано (Результаты)**

Я разработал и задокументировал **7 тест кейсов** для проверки экрана отметки посещаемости. Также провел ручное тестирование интерфейса в эмуляторе.

### **2.1. Подготовленные тест кейсы (TEST\_CASES.md)**

**TC 05\. Отметка статуса «Присутствовал»**

* **Предусловие:** Создано занятие, в группе 3 студента.

* **Шаги:** Открыть экран занятия, выбрать первого студента, установить статус «Присутствовал», нажать «Сохранить».

* **Ожидаемый результат:** Появляется сообщение «Сохранено 3 отметки» (или 1, если сохраняли по одному). В базе данных статус студента обновлен.

**TC 06\. Отметка статуса «Отсутствовал»**

* **Шаги:** Выбрать студента, установить статус «Отсутствовал», сохранить.

* **Ожидаемый результат:** Статус сохранен. При повторном открытии экрана отображается корректно.

**TC 07\. Отметка статуса «Опоздал»**

* **Шаги:** Выбрать студента, установить статус «Опоздал», сохранить.

* **Ожидаемый результат:** Статус сохранен без ошибок.

**TC 08\. Пустой список студентов**

* **Предусловие:** Создано занятие для группы, в которой нет ни одного студента (или все удалены).

* **Шаги:** Открыть экран отметки посещаемости.

* **Ожидаемый результат:** Показывается понятное сообщение (например, «В группе нет студентов»), приложение не падает.

**TC 09\. Повторная отметка (изменение статуса)**

* **Предусловие:** Студент уже имеет статус «Присутствовал».

* **Шаги:** Открыть экран занятия, изменить статус этого студента на «Опоздал», нажать «Сохранить».

* **Ожидаемый результат:** Статус перезаписывается. В базе остается одна запись для этого студента на эту дату (дубликатов нет).

**TC 10\. Изменение статуса до сохранения**

* **Шаги:** Назначить студенту статус «Отсутствовал», затем перед нажатием кнопки «Сохранить» поменять на «Присутствовал».

* **Ожидаемый результат:** Сохраняется последний выбранный статус («Присутствовал»).

**TC 11\. Отображение списка из нескольких студентов**

* **Предусловие:** В группе не менее 5 студентов.

* **Шаги:** Открыть экран занятия.

* **Ожидаемый результат:** Все студенты отображаются в списке (через RecyclerView или ScrollView), элементы не наезжают друг на друга, у каждого есть радио-кнопки/спиннер для выбора статуса.

## **3\. Найденные дефекты**

В ходе ручной проверки я выявил два дефекта, которые передал LD.

* **Дефект BUG 01 (Критический):** При пустом списке студентов экран падал с ошибкой NullPointerException.  
  * *Причина:* LD не предусмотрел проверку на пустой список (isEmpty()) перед настройкой адаптера.

  * *Статус:* Исправлено LD (добавлено сообщение «Нет студентов»).

* **Дефект BUG 02 (Средний):** При повторном заходе на экран занятия статусы студентов сбрасывались на дефолтные, хотя в текущем сеансе ранее сохранялись.  
  * *Причина:* Отсутствие загрузки сохраненных данных из временного кэша при открытии Activity. (Полноценное сохранение в Room будет только в Спринте 4).

  * *Статус:* Принято решение отложить полное исправление до Спринта 4, когда подключим базу данных. На текущем этапе добавили заглушку с уведомлением.
